# 使用示例

## 示例一：诊断

**输入**：体检技能诊所

**执行**：
```
1. 确定意图 → 诊断
2. 读取文件 → SKILL.md + modules/
3. 检查结构 → Keywords(8) + Summary(8) + Strategy(8) + AVOID(6) = 30
4. 检查触发 → metadata.trigger存在 = 10
5. 检查内容 → 语言简练(15) + 信号密度(10) + 可执行性(8) + 裁量空间(3) = 36
6. 检查实践 → 渐进式披露(8) + Human-in-the-Loop(5) + CLI友好(4) = 17
7. 总分 → 30+10+36+17 = 93
8. 等级 → S
```

**输出**：
```
总分：98/100
等级：S
建议：保持现状
```

## 示例二：创建简单技能

**输入**：创建代码审查技能

**执行**：
```
1. 收集需求：
   - 名称：代码审查
   - 描述：审查代码质量
   - 触发：代码审查、code review
   - 输入：代码路径
   - 输出：审查报告
2. 判断 → ✅ 值得沉淀
3. 选择 → 简单模板
4. 创建 → 代码审查/SKILL.md
5. 验证 → 通过
```

**输出**：
```
已创建：代码审查/SKILL.md
```

## 示例三：创建复杂技能

**输入**：创建文档生成技能，支持多格式

```

   - 输入：项目路径

3. 选择 → 复杂模板（模块化）

   - DocGen/SKILL.md
```

```
    ├── 01-analyze.md
    ├── 02-generate.md
    └── 03-export.md
```

## 示例四：先例研究

**输入**：查重，有没有类似代码审查的技能

**执行**：
```
1. 确定意图 → 先例研究
2. 提取关键词 → 代码审查、code review
3. 本地搜索 → 扫描 ~/.codebuddy/skills/*/SKILL.md
4. 远程搜索 → npx skills find "code review"
5. 汇总结果 → 按相似度排序
6. 输出建议 → 可复用/可合并/需新建
```

**输出**：
```
先例研究结果：
| 来源 | 技能名 | 相似度 | 可复用部分 |
|------|--------|--------|-----------|
| 本地 | 代码审查 | 100% | 已存在 |
| skills.sh | code-review-skill | 70% | 审查规则 |
| 结论 | 已有代码审查技能，无需新建 |
```

## 示例五：评估门禁

**输入**：门禁检查技能诊所

**执行**：
```
1. 确定意图 → 评估门禁
2. 读取技能文件 → SKILL.md + modules/
3. 触发评估 → 结构完整、信号密度>80%、Token<300
4. 发布门禁 → metadata.trigger存在、SKILL.md<200行、有示例、AVOID>=3
5. 输出结果 → 通过/不通过
```

**输出**：
```
门禁检查结果：
- 触发评估：✅ 通过
- 发布门禁：✅ 通过
- 建议：可发布到ClawHub
```

## 示例六：运维反馈

**输入**：反馈，搬题姬URL抓取超时

**执行**：
```
1. 确定意图 → 运维反馈
2. 记录反馈 → 技能名、问题描述、类型
3. 分析反馈 → 失败信号、高频问题
```
