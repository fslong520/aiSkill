# Step 2：撰写题解

## 前置条件

- 已获取题面（来自 `01-prepare.md`）
- 已与用户确认深度偏好
- 若有标程文件，已读取待用

## 核心原则

**因题制宜，无固定模板。** 以下只是方向性约束，不是结构要求。

### 必须覆盖的六项内容

| # | 内容 | 说明 | 简单题 | 中难题 |
|---|------|------|--------|--------|
| 1 | 直觉入口 | 读完题的第一反应 | 一两句带过 | 展开写暴力思路 |
| 2 | 关键转折 | 什么观察让你找到正解 | 直接说思路 | 展示歧路→正解 |
| 3 | 代码 | 带注释的代码 | 关键行加注 | 逐段精讲 |
| 4 | 复杂度 | 时间 + 空间 | 必须写 | 必须写 |
| 5 | 常见陷阱 | 易踩的坑 | 可省略 | 2~3 条 |
| 6 | 样例保真 | 原样保留 | 必须 | 必须 |

### 组织方式：自由

六项内容可自由排列组合。以下只是**可能性示例**，不是模板：

```
写法 A：先贴代码 → 再分段解释 → 最后总结坑
写法 B：先推演思路 → 边推演边贴代码片段 → 最后贴完整代码
写法 C：先讲暴力 → 撞墙 → 优化三步走 → 代码收尾
```

选哪种取决于题目特点。关键是**让读者读起来顺畅**，不是套格式。

### 推荐布局（今日实战沉淀）

经实战验证的成熟结构，尤其适合同中难题，可作默认骨架：

```
## X - 标题 题解

### 题目一句话     —— 一行说清题意
### 怎么想         —— 思维过程：朴素→卡点→关键观察（含规律发现路径）
### 关键点         —— 核心洞察，一句话点透
### 逻辑链         —— Mermaid 居中图（flowchart，见「Mermaid 图表使用指南」）
### 复杂度         —— 时间 + 空间
### 参考代码       —— 见「代码处理规则」，配「点评」
（### 易错点）     —— 中难题必配：UB/边界隐患 + 修正写法
```

因题制宜：简单题合并"怎么想/关键点"，深难题把"怎么想"拆多步。结构是参考，不是枷锁。

## ⚠️ 公式写法（析题特有）

数学公式必须配**具体数值例子**，公式和例子不可分离。

### 错误示范

```
不好：concat(x,y) ≡ x + y (mod M)
```

读者可能不认识 `≡`、不知道 `mod` 怎么算、不知道 concat 是什么。一段话塞三个黑话。

### 正确示范

```
好：
"≡" 读作"同余于"，意思就是"余数相等"。
concat(2,1) = 21，21 ÷ 2 = 10 余 1
x + y = 2 + 1 = 3，3 ÷ 2 = 1 余 1
余数都是 1，所以 (2,1) 满足条件 ✓
```

### 规则

1. **每个参数举一个具体数字**（x=2, y=1, M=2 这种小的）
2. **一步步演示计算过程**，不要跳步
3. **说清符号含义**——`≡` 是什么、`mod` 是什么意思——默认读者不知道
4. **用完例子马上回到通用公式**：例子是垫脚石，不是终点

## 歧路展示的基本原则

中难题必须包含「错误直觉→撞墙→修正」的叙述弧：

### 通用结构

```
问题：________
第一反应：________（为什么这是自然的）
为什么不对：________（具体反例）
转折观察：________（什么让你醒悟）
修正后：________（正确解法）
```

### 因果链条铁律（哥哥 2026-08-22 严令）

上述结构是骨架，血肉是**来龙去脉的因果链**——每个环节之间必须用「因为…所以…」接通：

```
发现了什么：手推样例观察到 X 现象（第一反应为何不够的根子）
因为什么：   现象背后的原因（不变量/重复计算/性质）
所以用什么： 原因直接推出算法（性质 → 数据结构/套路）
怎么写的：   算法落到代码（关键行 = 性质的直接翻译）
```

写法要求：
- 「怎么想」每步都必须问「为什么」——发现现象后追问"为什么必然"，把现象升格为性质，再让算法从性质里"长"出来
- **禁止甩结论**："观察到 XXX，用 YYY"（跳因果）；"显然/易知"（藏因果）
- 因果链要**显式**——宁可多写一句"因为…所以…"，不可让读者自己脑补
- 与 SKILL.md 4e 铁律一致；与「规律发现路径」（发现→追问→性质）配套，因果链把这条路径一路贯通到代码

### 反例选择指南

寻找反例的原则：

- **边界值**：N=1, 最小/最大输入
- **全同**：所有元素相同（全黑、全零）
- **聚集**：同类元素聚在一起（而非均匀分布）
- **极端形状**：单行、单列、1x1

## 从今日实战提炼的技巧

### 「对面视角」技巧

当问题从某个视角难以处理时，主动从对立面切入。

典型案例——ABC460 D 反复涂色：

```
第一视角（到最近 '#' 的距离）→ 对 '.' 格子有效
对面视角（到最近 '.' 的距离）→ 对 '#' 格子有效
两者互补 → 完整覆盖全部格子
```

在题解中标注「换视角」的时刻，帮助读者建立思维灵活性。

### 「规律发现路径」（今日实战沉淀）

写"怎么想"时，按三步展示规律如何被**发现**，而非直接甩结论：

1. **手推样例找结构**——小样例跑一遍，找变化中的不变量。
   > ABC471 C：手推 `-11 -4 -1 2` 取曲奇全程，发现已取集合在排序序列里始终连续。
2. **追问"为什么必然"**——把现象升格为性质。
   > 为什么必然连续？最近未取点只能是已取区间的左右外侧邻居——内侧已取光，外侧之外更远（数轴单调）。
3. **性质翻译成算法**——连续区间 + 两侧候选 → 双指针两端扩展。

```
不好：观察到已取集合连续，双指针即可
好：  手推样例发现已取集合始终是连续区间
      → 问：为什么必然？→ 最近未取点必在区间左右外侧
      → 性质：候选只有两个 → 双指针两端扩展
```

### 边界值排查清单

写完解法后，主动用以下清单排查：

| 检查项 | 案例 | 今日教训 |
|--------|------|---------|
| 最大值是否需要多一位/多一轮 | N=10^18 是 19 位不是 18 位 | E 题漏了 k=19 |
| 全同输入是否退化 | 全黑格 BFS 失效 | D 题全黑特判 |
| 1x1 极端 | 1x1 `#` 输出 `.` 不是 `#` | D 题边界 |
| 聚集模式是否异常 | 黑块中心白格触发失败 | D 题双 BFS 修复 |

## 多题（比赛）场景

若题目有多道（如 ABC A~E）：

- **默认合一文件 + typst PDF**：所有题写进一个 typst 文件（如 `abc471_题解_A-E.typ`），题与题独立成节，不散文件（用户要求分开除外）
- **题与题独立**：每道题自成一节，读者可以只看卡住的那题
- **深度差异化**：A/B 浅写，C/D 中度，E/F/G 深度展开
- **末尾串讲**：一段话或一张表，概括各题核心技巧与思维递进关系
- **不写逐题动画**：多题用**静态组图**表示变化（`#snapshots` 状态组图 / `#booktabs` 三线表 / 流程图），见 `templates/example-multi.typ`
- 产物判据：多题 → typst PDF；单题 + 需动图 + 哥哥未指定 typst → HTML；单题 + 哥哥强调 typst 或单题无动图 → typst PDF

### typst 语法要点（易错，全部踩过坑）

- 数学公式 `$...$`，比较符写 `<=` / `>=` / `!=`，**勿写 `leq`/`geq`**（typst 未定义）
- **数学模式禁中文**（`$sum 分子$` 报错）；代码变量名（`dp`/`par`/`cross`/`lca`）用反引号 `` `dp` ``；连写变量 `$O(NM)$` 报错须 `$O(N M)$`
- **表格公式 cell 用 content**：`("B", [前缀和 $|S-2P_k|$ 一趟扫描])`——字符串 `"$...$"` 不渲染公式
- **函数参数内去 `#`**：`#booktabs(...)` 内写 `strong[...]` 不写 `#strong[...]`（代码模式）
- `#` 在正文须转义 `\#`
- **SVG 字体**：SVG 内 `font-family` 只写 `"Noto Serif CJK SC"`，**禁斜体**——否则中文回退隶书（STLiti）
- 代码块直接用三个反引号（codly 自动美化），前置 `#show: code-init`
- 图注用 `#captionless[...]`（小字灰禁斜体）
- `#booktabs(("表头1","表头2"), (("行1a","行1b"), ("行2a","行2b")))`——rows 是**扁平**行数组，勿嵌套
- 字体：Libertinus Serif（西文）+ Noto Serif CJK SC（中文），`pdffonts` 验证无 STLiti
- import 用**相对路径**（typst 不支持绝对路径）：`#import "theme-academic.typ": *`

## 代码处理规则

- 若用户提供了标程文件路径 → 必须逐关键行精讲该标程
- 若用户没给标程 → 自己写实现，或引用已知解法
- 关键行加注：不写 `// 循环` 这种废话，要写 `// 左子树：中序[l, p-1]`
- **代码风格**遵循主技能文档第 5 节「代码风格约定」——短变量、全局、少传参、左大括号另起一行
- **传参优化**：多参数递归优先改写成「全局光标 + 区间边界」模式

### 用户自带代码（今日实战沉淀）

用户提供自己的代码时：

1. **逐字摘录主逻辑**——模板头（`#include`/`#define`/`using`/`const` 常量）从略但注明"完整文件见 xxx，模板头从略"；主逻辑（变量声明起）与其源文件**逐字一致**，勿改写、勿擅自"优化"
2. **一致性校验**——写完对每个代码块与源文件逐字比对（去模板头），不一致必修正
3. **隐患排查**——审视未定义行为与边界漏洞，如：
   | 隐患 | 今日案例 |
   |------|---------|
   | erase 后使用失效迭代器 | ABC471 D：`s.erase(it);` 后用 `*it` → 应先取值再删 |
   | 数组负下标越界 | ABC471 E：`C(n-2, k-2)` 在 k=1 时访问 `inv[-1]` → 组合数判 `b<0` |
   | 整数除法截断 | ABC471 A：`a/b==9` 误判 19/2 → 判整除或浮点 |
   | 比较符边界 | 平局处理、`<=` vs `<` |
   在「易错点」小节指出并**给修正写法**，措辞"曾踩坑/需修正"
4. **点评**——正确处肯定（"空串哨兵法，写法干净"），问题处指正，全程老师口吻，禁"你的代码"

### 代码风格速查

| 场景 | 不好 | 好 |
|------|------|-----|
| 根节点变量 | `int root = pre[l1];` | `int rt = a[k++];` |
| 递归传参 | `dfs(l1+1, l1+l, l2, p-1);` | `dfs(l, p-1);` |
| 多行注释 | `// 这里递归处理左子树` | `// 左子树：中序[l, p-1]` |
| 存结果 | `vector<int> ans; ans.push_back(rt);` | `cout << rt;` 或 `ans[++cnt] = rt;` |

## 留空练习模式（仅按需启用）

**默认不挖空。仅在用户说「留空」「挖空」「填空」时启用。**

启用后写作方式调整如下：

1. **文字描述中嵌入答案**——将挖空处的答案显式写在代码前的文字里
   ```
   好：在文字中写"用 a[k++] 取前序当前位置为根，光标后移"
       代码中留空 char rt = _______;
   ```
2. **挖 3 空**——只挖核心逻辑：
   - 递归出口条件（`l > r`）
   - 关键操作（如何取根）
   - 比较对象（`b[p] != rt` 中的 `rt`）
3. **开头加说明**——「下面代码挖去了若干关键处，答案已在前面描述中，仔细读一遍就能填上。」
4. **不走样**——留空不影响代码可读性，`______` 长度统一为 6 个下划线

## Mermaid 图表使用指南

### 何时用 Mermaid

| 内容 | 用 Mermaid | 用 Table |
|------|-----------|----------|
| 算法主流程 | ✅ flowchart TD | — |
| 构造/转换步骤 | ✅ flowchart LR | — |
| 思维分支 | ✅ flowchart TD | — |
| 复杂度对比 | — | ✅ 表格更清晰 |
| 样例验证 | — | ✅ 表格更清晰 |
| 公式推导 | — | ✅ 文字+公式 |

### 布局规范（HTML 产物）

- ⚠️ **Mermaid 图整体居中由 CSS 保证**（模板 `.mermaid { text-align:center }`），无需手动包裹 div
- **`<pre class="mermaid">` 内源码必须顶格书写**——第一列即写 flowchart，无缩进；缩进会被当作节点文字的一部分，导致渲染错乱：

```
<pre class="mermaid">
flowchart TD
A["步骤"] --> B["结果"]
</pre>
```

### Mermaid 模板库（HTML 语境，源码顶格）

**模板 1：算法主流程**
```
<pre class="mermaid">
flowchart TD
Start([开始]) --> Input["输入"]
Input --> Step1["步骤1"]
Step1 --> Step2["步骤2"]
Step2 --> Output["输出"]
Output --> End([结束])
</pre>
```

**模板 2：构造步骤链**
```
<pre class="mermaid">
flowchart LR
A["输入"] --> B["处理1"] --> C["处理2"] --> D["输出"]
</pre>
```

**模板 3：决策分支**
```
<pre class="mermaid">
flowchart TD
A{"条件判断"} -->|是| B["路径1"]
A -->|否| C["路径2"]
</pre>
```

**模板 4：代码执行推演**
```
<pre class="mermaid">
flowchart TD
subgraph "执行过程"
A["初始状态"] --> B["第1轮"] --> C["第2轮"] --> D["最终结果"]
end
</pre>
```

### 样式规范

- 起点：`style Start fill:#ff9800,color:white`
- 终点：`style End fill:#ff9800,color:white`
- 正常步骤：`style A fill:#e3f2fd`
- 判断节点：`style B fill:#fff3e0`
- 成功结果：`style C fill:#c8e6c9`
- 失败结果：`style D fill:#ffcdd2`

### 禁忌

- ❌ 不用 pie chart（渲染效果差）
- ❌ 不用超过 8 节点的单链（改用 table 或拆分）
- ❌ 不用多层嵌套 subgraph（保持扁平）
- ❌ 不在 flowchart 里放长文本（用 table）
- ❌ mermaid 源码缩进书写（节点文字会被污染）

## HTML 产物组装与验证（仅限：单题 + 需动图 + 哥哥未指定 typst）

### 组装流程

1. **复制骨架**：将 `templates/example.html` 复制为 `<比赛>_题解.html`
2. **替换题头**：标题、一句话、标签
3. **逐题填充小节**：每道题一个 `<section class="xt-sec">`，内部按推荐布局写

7. **样例演示**：表格 `.xt-table` 逐步验证样例（每行一步：状态→变化→结果）
8. **多解法递进（中难题）**：暴力 → 卡点 → 优化 → 最优，每解配代码片段
9. **动态可视化（中难题必配）**：仿模板 B 题双指针动画——`.xt-viz` 容器 + steps 预计算 + 四钮控制条 + 解说行（详见下方「动态可视化规范」）
10. **代码块**：`<pre class="xt-code"><code class="language-cpp">` 包裹，OI 风格，注释规则不变；行号由模板 JS 自动生成（勿手工加号）
11. **公式**：`$...$` 行内、`$$...$$` 行间，KaTeX 自动渲染
12. **多题串讲**：末尾 `<section class="xt-summary">`
13. **文件名**：`<比赛/题目>_题解.html`，多题合一（如 `abc457_题解_A-E.html`）

### 动态可视化规范（中难题必配）

中等难度（≥250 分）及以上的题，思路讲解后必须配**步进动画**演示算法过程：

1. **抄模板**：B 题（双指针）已实现完整动画引擎，直接复制改数据。不同算法改 steps 生成逻辑即可
2. **steps 预计算**：先用算法逻辑跑一遍小数据，把每步的 {状态, 解说文字} 存入数组；渲染是"状态回放"
3. **控制条四钮**：▶ 播放 / ⏸ 暂停 / ⏭ 单步 / ⟲ 重置——必须有，教学场景不允许只自动播放
4. **解说行**：每步显示状态文字（如 `a[0]=2 + a[4]=15 = 17 > 11 → r--`），与格子高亮同步
5. **数据规模**：动画用样例或 ≤8 个元素的小数据，格子 48px；数据大改用表格
6. **anime.js 用法**：可做格子脉冲/位移过渡（如 `anime({ targets, scale:[1,1.15], duration:200 })`），核心仍是状态渲染

**动画类型→实现提示**：

| 算法 | 可视化 | 做法 |
|------|--------|------|
| 数组扫描/最值 | 格子扫描高亮 | 每步高亮当前格子+更新 mx 值 |
| 双指针/二分 | 左右指针移动 | 模板 B 题原样 |
| 排序 | 交换/冒泡 | steps 记录每次交换的下标对 |
| BFS/DFS | 节点着色 | 格子或节点阵列，按访问序着色 |
| DP | 表逐格填充 | 二维格子，每步填一格 |
| 贪心/构造 | 状态变化 | 仿 B 题 |
