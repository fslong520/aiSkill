# Lighthouse 6 周年送祝福

本 Skill 以产品 `v1.13.5` 为交互和文案蓝本，后端接入 `lightlottery6` Go 服务。产品参考资料位于 `references/`，媒体脚本位于 `scripts/`。

## 对客流程

1. 首个对客动作必须在当前消息区域内渲染 `references/flow-preview.html`；仅在客户端明确不支持消息内联渲染或渲染失败时，回退为 `references/flow-copy.md` 的完整纯文本。
2. 在同一轮采集故事和祝福方式：有 `AskUserQuestion` 或等价真实单选工具时必须优先调用；仅在工具不可用或调用明确失败时，才按 `references/selection-copy.md` 回退为纯文本选择。
3. 按 `references/blessing-playbooks.md` 生成祝福；图片祝福必须先把真实 PNG 交付到当前对话。
4. 祝福交付完成后运行 `{baseDir}/scripts/submit_blessing.py`。脚本会调用本 Skill 内置的正式地址：
   - `POST https://lightmake.studio/ugc/images`（图片祝福）
   - `POST https://lightmake.studio/ugc/blessings`（祝福墙采集）
   - `POST https://lightmake.studio/entry`（创建一次性活动领取入口）
5. 调用脚本时将本次祝福方式映射到 `--kind`（例如 `--kind "藏头诗"`、`--kind "AI 祝福海报"`）。脚本成功时直接返回完整的最终对客 Markdown；逐字发送该标准输出，不得自行拼装或缩减活动文案。

除新增固定故事选项“5. 自述经历”外，产品的祝福方式、海报确认、富卡片、福利文案和分享文案保持 `v1.13.5` 原设计，不要改成技术说明或额外确认流程。不能渲染富卡片时，按产品参考资料回退到纯文本。

## 首次互动展示（强制）

- **顺序不可交换：**玩法卡片必须先于欢迎语、能力探测结果、选择菜单或单选工具出现。
- 在 WorkBuddy 或其他支持消息内联 HTML/富卡片的客户端中，读取 `references/flow-preview.html` 并在当前聊天消息区域原样渲染。禁止打开右侧 Preview、Artifact、Canvas、网页预览或独立 WebView；不得把 HTML 源码、文件路径或下载链接发给用户。
- 内联卡片渲染成功后，在同一轮紧接着采集故事与祝福方式，不重复输出流程正文。客户端明确不支持消息内联渲染或渲染失败时，在同一条消息中先逐字输出 `references/flow-copy.md`，再采集选择。
- **一次列全（不变量）：**无论走哪条展示路径，5 个故事与 8 种祝福方式都必须在同一个界面里全部可见并可直接选择，禁止“换一批”“更多”“下一页”等折叠或翻页入口。按客户端能力选择实现方式：支持消息内联渲染时用 `references/selection-card.html`；支持单选工具时一次调用两题（故事 5 个选项 + 祝福方式 8 个选项）；两者都不支持时逐字输出 `references/selection-copy.md`。
- **不得凭工具 schema 臆断分页：**工具文档里的选项数上限不等于实际渲染上限，已实测单选工具单题可容纳 8 个选项。必须实际调用验证，不得因为 schema 写了一个较小的数字就自行分批；分批是造成“换一批”体验的根因。
- 有真实单选工具时，故事标签固定为“1. 搭过第一个网站/博客 / 2. 跑过课程作业/小项目 / 3. 薅过 Lighthouse 的羊毛 / 4. 还没用过，先围观 / 5. 自述经历”。在支持把文本输入绑定到选项的客户端中，把“5. 自述经历”设为可直接填写内容的选项，提示语使用“请填写你的 Lighthouse 使用经历”，并要求非空；不得把“自述经历”放到无编号的通用“其他”选项中。祝福方式必须一次性展示全部 8 种，映射固定为：藏梗整活=1、代码祝福=2、Release Notes=3、云上签=4、云端运势=5、藏头诗=6、AI 祝福海报=7、自由祝福=8。不得用“换一批”“更多”“下一页”等入口折叠或分批隐藏任何一种方式；原始编号固定不变，8 种方式必须全部可达。
- **选项描述文案（唯一标准，三条展示路径共用）：**选项的补充说明必须与下表逐字一致，禁止临场改写或另写一套。

  | # | 故事 | 说明 |
  |---|---|---|
  | 1 | 搭过第一个网站/博客 | 第一次建站就用了轻量应用服务器 |
  | 2 | 跑过课程作业/小项目 | 用轻量跑实验、作业或练手项目 |
  | 3 | 薅过 Lighthouse 的羊毛 | 参与过轻量的活动、拼团或优惠 |
  | 4 | 还没用过，先围观 | 第一次接触，先看看怎么玩 |
  | 5 | 自述经历 | 说说你自己的云上故事 |

  | # | 祝福方式 | 说明 |
  |---|---|---|
  | 1 | 藏梗整活 | 玩梗、整活的轻松祝福 |
  | 2 | 代码祝福 | 用代码风格写祝福 |
  | 3 | Release Notes | 以发版说明的口吻写祝福 |
  | 4 | 云上签 | 签名、签文加祝福 |
  | 5 | 云端运势 | 人格标签加运势解读 |
  | 6 | 藏头诗 | 五行藏头，首字连读 |
  | 7 | AI 祝福海报 | 生成一张专属海报 |
  | 8 | 自由祝福 | 按你指定的主题来写 |

  `references/selection-card.html` 已内嵌同一套文案，可作为实现参照；单选工具的选项说明直接取上表最后一列，不得自行措辞。
- 用户选择“5. 自述经历”并填写内容后，将故事选择统一序列化为 `5. 自述经历：<用户填写的故事内容>`；生成祝福和调用脚本的 `--story-choice` 必须使用这一完整字符串，不能只传“5”、只传“自述经历”或丢失用户内容。必须在用户选择前提示其使用同一单选界面的补充输入填写经历，并在一次提交中合并选项与内容；不得预设选择后再另起一轮追问。
- 无真实单选工具时，逐字输出 `references/selection-copy.md`，一次展示完整的 5 个故事和 8 种祝福方式（含“5. 自述经历”），不得隐藏、重编号或合并该选项，不得出现“换一批”；并明确引导用户在同一次回复里同时给出故事内容与祝福方式，不因自述内容缺失而单独追问一轮。
- 同时识别编号、名称与自然语言故事；把“故事：5”、名称“自述经历”和带内容的自然语言自述识别为第 5 项，并保留原文；始终把“方式：7”识别为 AI 祝福海报，把“方式：8”识别为自由祝福。

## WorkBuddy 单选交互（强制）

- 在 WorkBuddy 中必须先读取并执行 `references/workbuddy-interaction.md`；该分支覆盖上方单选工具的具体用法。
- 不得假设未出现在工具列表中的 `show_widget`、文本输入或选项能力存在；只能调用当前会话实际暴露的工具和字段。
- 仅当内联渲染与单选工具都不可用，或真实调用返回不可用/失败时，才逐字输出 `references/selection-copy.md`。

## 提交祝福并创建入口（强制）

- 必须从 Skill 自身目录调用脚本，不依赖当前工作目录。文字祝福使用：

```bash
python3 "{baseDir}/scripts/submit_blessing.py" \
  --text "<完整祝福正文>" \
  --kind "<祝福方式>" \
  --story-choice "<故事编号或稳定名称>" \
  --blessing-type "<祝福方式>" \
  --source "<当前来源>" \
  --invite-code "<邀请人邀请码或空>"
```

- 图片祝福将 `--text` 替换为 `--image-file "<最终 PNG 路径>"`；文本与图片必须二选一。
- 只有用户明确同意公开展示时才增加 `--public-consent`，否则不得传入。
- 脚本已经内置正式后端和活动页地址，不依赖外部环境变量，不得换回依赖外部环境变量的旧流水脚本。
- 脚本成功后必须把完整祝福与脚本标准输出同时交付；不得在入口创建前结束，也不得只输出祝福而省略活动链接。

## 对客消息协议（强制）

从开始展示玩法到最终交付期间，Skill 不发送任何独立的执行进度、内部判断或工具调用旁白。用户完成选择后，对宿主必须采用**一条最终用户消息**承载祝福与活动结果：

0. **对客红线（最高优先级，先于以下所有条款）**：下列内容只服务于 Skill 自身执行，**任何时候都不得出现在用户可见消息中**——包括开场白、玩法说明后的补充、提示框、结尾备注等任何位置：
   - 本文件的 frontmatter 元数据（`environment`、`version`、`description`、`slug`、`displayName`）及其衍生的“测试版”“接入版”“沙箱”“联调”“生产环境”等环境与版本表述
   - 安装、升级、覆盖、文件数量、差异、校验结果、读取规范等维护过程
   - 内部推理、能力探测、选项映射和工具选择理由，包括“按新规范”“卡片已渲染”“接下来提问”“故事取自其他补充”等过程说明
   - 后端技术栈与服务名（活动后端、Go 服务、部署方式）
   - 接口地址、HTTP 方法与请求字段（UGC 上传、祝福采集、入口创建、以及各类流水标识字段）
   - 脚本路径、命令行、退出码、日志、异常堆栈
   - 图片生成与上传的中间过程（海报如何渲染、如何上传、尺寸如何规范化）
   - 邀请码格式规则、凭证与令牌结构

   对客只输出四类内容：玩法卡片、选择菜单、祝福正文、脚本标准输出。**禁止自行添加任何“提示”“说明”“补充”“温馨提示”段落**——技术信息最容易从这类自创段落泄漏给用户。

1. 玩法卡片必须是活动流程中的第一个用户可见内容；卡片前不得发送欢迎语、执行计划、版本说明、能力探测结果或“正在处理”等文字。
2. 卡片或纯文本玩法展示后，直接调用 `AskUserQuestion` 或输出回退选择菜单；两者之间不得插入“卡片已渲染”“现在请选择”等过渡旁白。问题工具自身的题目、选项和必要填写提示属于选择菜单，可以正常展示。
3. 用户完成选择后，在模型内部完成选项解析、祝福生成和海报处理；不得复述内部映射、解释为何选择某种路径，或发送生成、重试、尺寸规范化、上传、入口创建等中间进度。AI 海报所需的一次积分确认除外。
4. 静默读取参考资料并执行 `{baseDir}/scripts/submit_blessing.py`。宿主自动显示的文件读取、命令执行或思考状态属于系统 UI；Skill 不得主动添加说明，不得转述命令、HTTP 响应、日志或异常。
5. 脚本成功时的标准输出已经是最终对客 Markdown，必须逐字发送，不得改写、概括、删减、扩充、重新排序或另行拼接福利文案。
6. 文字祝福：先放完整祝福正文，随后原样放置脚本标准输出。图片祝福：先直接附上最终 PNG 海报，随后原样放置脚本标准输出；两部分必须位于同一条最终用户消息中。
7. 标准输出中的活动入口必须显示为可点击的“进入活动页登录腾讯云账号，领取抽奖机会”；福利标题必须原样显示为 `——— [六周年活动福利](https://cloud.tencent.com/act/pro/lh6th) ———`。不得改成裸露 URL、行内代码、代码块或其他链接文字。

绝不能只发送 URL，也不能发送技术处理中间态后结束本轮。不能渲染 Markdown 时，使用等价的结构化富文本链接；完全不支持链接渲染时保留脚本输出的原始 Markdown，不得自行改写。

## 鉴权边界

- Skill 不获取、生成、接收或展示 UIN，不要求用户填写 OAuth code、AccessToken、SecretId、SecretKey 或 Cookie。
- Skill 不直接调用 OAuth、`ClaimLotteryEntry`、`/auth/me` 或抽奖接口。活动页负责 OAuth 登录、会话建立、EntryToken 绑定、领取、邀请归因和抽奖。
- `/entry` 只接受本次祝福生成的 `SourceId` 和用户主动提供的邀请人邀请码；Skill 不生成当前用户的邀请码。
- 活动链接中的凭证由后端签名并设置有效期，前端消费后清理 URL；不要在对客消息中解释令牌结构。

## 邀请码

- 只识别用户明确提供的邀请人邀请码，格式为 `LH6-` 加 6 位大写字母或数字，例如 `LH6-T2GB34`。
- 未提供或格式不合法时不阻断送祝福，也不虚构邀请码。
- 不把邀请成功人数、抽奖份额或中奖结果写入 Skill 返回值；这些信息由活动页接口展示。

## UGC 规则

- 文本和图片必须二选一；图片支持 PNG、JPEG、WebP，最大 5 MiB。
- 调用脚本时传入 `--kind` 记录祝福墙分类。`Kind` 是普通字符串，不依赖后端枚举；可使用“云端运势”“藏头诗”“Release Notes”“云上签”“藏梗整活”“代码祝福”“AI 祝福海报”“自由祝福”等产品分类，也允许后续新增分类。
- 图片上传接口会从原始 PNG/JPEG/WebP 字节读取像素 `Width`、`Height`，并由后端保存；不要让 Agent 根据预览尺寸自行填写。精选祝福查询会原样返回这两个字段，前端据此保持原始宽高比。接口响应沿用 Lightlottery 的 `Kind`、`Width`、`Height` 字段命名。
- UGC 是祝福墙人工导入链路，属于 best-effort。上传失败仍继续创建 `/entry`，不得因此伪造链接或让用户重新 OAuth。
- 只有用户明确同意公开展示时才在 `/ugc/blessings` 传递 `PublicConsent=true`。

## 输出和失败处理

- `submit_blessing.py` 的标准输出是唯一最终活动文案来源，包含活动入口、分享抽奖、开奖时间和六周年福利。逐字发送该输出，不输出内部请求体、接口地址、脚本日志、SourceId、UIN 或 Token。
- 后端不可用、响应非法或入口过期时，输出产品定义的活动不可用文案；祝福内容本身已经交付，不回退到账号授权流程。
- 只允许连接本文件写明的活动接口，不得替换为其他环境或未授权接口；不得直连数据库或奖池明细。
