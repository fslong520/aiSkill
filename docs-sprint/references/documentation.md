# 文档组织与格式

优先沿用当前项目的文档位置、任务格式与状态体系；下文是在没有既有约定时可采用的默认结构。派发、任务状态和验收循环见[协作流程](workflow.md)，已有状态需对应到这些完成与暂停条件。项目文档记录自身约定，不反向依赖技能安装路径。

## 目录与内容

下列路径相对项目根目录；验收记录可使用系统临时目录下的绝对路径。文档使用 Markdown，按实际内容组织章节，不建立空目录或空章节。

| 文档类型 | 位置 | 最少内容 |
|---|---|---|
| 总索引 | `docs/INDEX.md` | 各文档区域的入口链接 |
| 实验记录 | `docs/research/{topic}/` | 问题、方法、可复现证据、结果、结论与局限 |
| 跨模块设计 | `docs/architecture/` | 目标、模块关系、数据与状态归属、接口、关键取舍、验收场景 |
| 专题设计 | 沿用 `docs/design/` 中对应主题 | 该主题的方案与验收依据；跨模块公共约定链接到所属架构文档 |
| 架构决策记录 | `docs/adr/` | 需要单独留痕的决策背景、备选方案、选择及影响 |
| 包入口 | `docs/packages/{package}/README.md` | 职责、上下游关系、模块与设计文档索引 |
| 模块设计 | 对应包文档下的 `{module}.md` 或 `{module}/README.md` | 输入、输出、状态、接口与错误约定 |
| 交付分析 | `docs/plan/analysis/{topic}.md` | 任务划分、依赖、跨模块对接与协作流程要求的调度记录 |
| 任务文件 | `docs/plan/tasks/{area}-{seq}.md` | 下述任务字段与正文；执行中持续更新 |
| 验收记录 | `{临时目录}/reviews/{uuid}.md` | 被审版本、结论、问题位置与证据、验证结果；判定标准见协作流程 |
| 剩余问题 | `docs/plan/backlog.md` | 不阻塞本次交付的剩余问题；已有问题文档时只引用 |

文档已有明确归属时更新原文件，不因阶段变化另建同主题副本。已有版本计划和历史记录沿用原位置；问题文档的状态与归档遵循项目约定。

## 任务格式

已有任务格式直接沿用；新建格式可用以下字段，任务状态的含义见[状态与协作](workflow.md#状态与协作)：

```yaml
id: {area}-{seq}
package: ...
module: ...
status: pending | ready | in-progress | done | blocked
depends-on: [task-id, ...]
```

`area` 可以是包或能力的前缀。任务正文包括：

- `objective`：可独立验收的交付结果。
- `context`：执行依据的设计文档，以及各依赖允许本任务启动所需的产出和版本。
- `path`：涉及的代码和文档路径。
- `verification`：验收场景、执行命令及完成后的实际结果。

## 设计文档状态

设计文档开头标注状态，与任务执行状态分别管理：

| 状态 | 含义 |
|---|---|
| `Draft` | 方案待讨论或验证，尚未定案 |
| `Finalized` | 设计已确认，可以据此实现 |
| `Implemented` | 已实现，文档与代码一致 |
| `Deprecated` | 已废弃，说明替代文档或停用原因 |

## 记录与维护

- 定案写回对应设计文档并更新状态；任务通过 `context` 引用，不复制另一套设计。沿用用户已给的授权与项目确认方式，不额外要求创建 PR。
- 设计变化时更新受影响任务的依据、输入版本和验收条件；已有验证结论是否仍有效按协作流程判断。
- 新建或移动文档时维护所属入口和相对路径链接；新增文档区域时更新项目已有总入口，采用默认结构时更新 `docs/INDEX.md`。索引只导航，不重复维护规则正文。
- 消融实验的删减项、保留理由和证据随对应设计或任务记录交接，不单独建立一套报告目录。
- 临时验收记录的结论、已验收代码版本、验证结果和剩余问题回写任务，避免恢复工作依赖临时文件。`docs/plan/reviews/` 中的现有记录保留为历史资料。
