# 多任务交付

先读取当前项目已有的工作规范和相关设计；没有固定文件名要求。创建或更新文档时读取[文档组织与格式](references/documentation.md)，组织多任务协作时读取[协作流程](references/workflow.md)。

1. 主 agent 作为用户的统一对接人，按[阶段分工](references/workflow.md#阶段分工)补齐实验与设计，已有定案直接进入开发安排。
2. 按[派发与上下文](references/workflow.md#派发与上下文)分配任务，区分约定依赖与运行依赖，提供任务依据、工作目录和确定的输入版本。
3. 执行[开发与验收循环](references/workflow.md#开发与验收循环)：独立验收未通过时，主 agent 继续派发开发修复并再次验收，直到通过或确实缺少无法自行取得的外部条件。
4. 持续接收结果、安排修复与集成，并按当前待办调配执行位置；完成条件和暂停条件以交付流程为准。

主 agent 可以直接承担开发或验证工作，但同一任务的开发和独立验收由不同执行者完成。

回复和交付语言沿用用户或项目约定。技能随产品安装在项目外，项目路径从当前工作目录解析，不从技能安装目录解析。
